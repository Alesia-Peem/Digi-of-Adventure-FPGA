## 1. Top level: instance, buttons, exit

```verilog
cr_core #(.MEM_DIR(MEM_DIR), .STEPS_PER_TICK(2), .TEST_MODE(0)) u_cr (
    .clk, .rst, .gtick,                      // input_hub gtick (60 Hz) -> 2 game steps of 1/120 s each
    .btn_left(lvl[2]), .btn_right(lvl[3]),   // levels (BTNL / BTNR)
    .ev_jump(on3 & ev_u),                    // BTNU press

    .enter(s3_enter),                        // new game at level 1
    .demo_cmd, .demo_op, .demo_arg,          // see 1.2
    .exit_req(cr_exit),                      // level-pulse: WIN screen confirmed
    .step_done(), .busy(),
    .mode(cr_mode), .level(cr_level), .cam_px(cr_cam_px), .q_idx(pub_idx), .q_data(pub_data));
```

Campus Run's own mapping (decision D3): BTNL/BTNR move, BTNU jump, **BTNC skill**, **BTND start/pause**.

### 1.1 Needed in `rtl/common/input_hub.v`: a BTNC press event

`input_hub` gives BTNC only as `ev_tap` (released before 0.8 s) and `ev_back` (held 0.8 s). The skill must fire
on the press, like the keyboard `E` key down. Request: one more output **`ev_c`** = `press[4]` latched per tick
exactly like `ev_u/d/l/r` (same `pend` mechanism, valid in the `gtick` cycle). Nothing else changes; Stage 1/2
keep using `ev_tap` / `ev_back`.
Test: `tb_units` — a 1-clock BTNC press between two ticks gives exactly one `ev_c` in the next tick cycle and
none in the one after.

### 1.2 Commands (`demo_cmd`, one clock; applied between steps, kept while the core is busy)

| op | name | arg |
|---|---|---|
| 1 | STAGE | restart at level `arg[1:0]` (1..3) — the F1/F2/F3 owner-mode stage select |
| 2 | PUT | player to x = `arg[8:0]`/2 m, y = `arg[13:9]`/2 m, standing `arg[14]` (test only) |
| 3 | SEED | random generator state = `arg` (0 means 0xACE1) |
| 4 | WIN | confirm on the WIN screen → `exit_req` |
| 5 | GOLD | the milk-tea power (the hub's `win` action needs stage 3 + GOLD; stage 3 has gold anyway) |

Demo-menu "jump to Stage 3, win" = STAGE 3, then the top drives the WIN screen through the normal game.

### 1.3 Exit

`exit_req` goes high on the WIN screen and stays high until the next restart. Like the hub wrapper
(`stage3_demo.py` `poll()` / `update()`): a BTNU (jump) press, or a BTND (menu) press made while the WIN screen
is already up, confirms after that tick's steps; op WIN does the same from the demo menu. The top only needs
`s3_exit = on3 && cr_exit` (rising edge). Test: `tb/cr_tb_ctrl.v` case 5.

### 1.4 7-segment and LEDs (proposal, nothing in Pygame to match)

The only board output of the original is the skill digit on AN0 (`cloak_digit` = ⌈skill/120⌉, 0..5).
Proposal: digits `H3 L s ttt` = hearts from the Stage 2 handoff (passed through unchanged, decision D4),
level, skill digit (blank when 0), ⌈time_left/120⌉ seconds. LED0..9 progress bar (progress/10), LED10 skill
ready, LED11 skill used, LED12 chase, LED13 interview. Values come from the publish fields in section 4.

## 2. Renderer: `bg_mode 6` — Campus Run tile layer + backdrop

Formats (generated by `tools/cr_assets.py`, docstring is the reference):

| ROM | depth × width | address | content |
|---|---|---|---|
| `cr_map.mem` | 12 288 × 9 | `level*4096 + row*256 + col` (row 0 = top) | `{hflip, tile_id[7:0]}`, tile 0 = empty |
| `cr_tiles.mem` | 204 800 × 4 | `id*1024 + y*32 + x` | colour index, 0 = transparent |
| `cr_tpal.mem` | 3 200 × 12 | `id*16 + index` | 0x0RGB |

Per screen pixel (x, y) of a world line: world row = `src_row(y)` (2.3), world x = x + cam_px32 (2.2);
tile = map[level][wrow/32][wx/32]; texel = tiles[id][wrow%32][hflip ? 31-wx%32 : wx%32]; if index ≠ 0 the
pixel is tpal[id][index], else the backdrop pixel (2.4). Water tiles also get the two bob lines of
`render.py:108-111` — the tile role (water) comes from `cr_water.mem` (bit `10 - row` of word `level*256+col`).

### 2.1 Inputs the renderer needs from the top

`cr_level[1:0]`, `cam_px32[12:0]`, `cam_frac` (2.2), `par_off[6:0]` (2.4), `time` for the bob lines
(`render.py:109` uses `g.time*4 + b.x`; the core can publish its step counter `now`).

### 2.2 Horizontal position — exact rule

`render.py` puts every tile at `x = round((col - cam)*32)` with Python's round-half-to-even, where `cam` is
metres. With cam in units, `cam*32 = cam/76 800`. When `cam % 76 800 == 38 400` (exactly half a pixel) tiles of
even and odd columns round in different directions. The frame model must reproduce that; I propose the
core publishes `cam_px32 = cam / 76 800` (floor) and the half-pixel flag, and the renderer shifts odd columns.
**Test:** frame check pixel-exact against `render.draw_frame()` world layer at cameras covering the tie.

### 2.3 Vertical: 352 → 360

The world image is 640 × 352 and `render.py:200` resizes it to 640 × 360 with NEAREST. Pillow's NEAREST takes
source row `floor((r + 0.5) * 352 / 360)` for output row r (to be confirmed by the frame model, not assumed).
HUD primitives are drawn afterwards in 360-row space.

### 2.4 Backdrop (QSPI flash, decision D1)

Three new pictures for `pic_list.py`, 704 × 352 each, built exactly like `render.sprite(BACKGROUND[s],
(704, 352))` (NEAREST resize of the source, `render.py:94`). Previews: `mem/preview/cr_bg1..3.png`.

| name | source (`onlystage_3/assets/`) |
|---|---|
| CR_BG1 | `sunset_2.png` |
| CR_BG2 | `mountains_1.png` |
| CR_BG3 | `night_3.png` |

704 B per row ≤ the 768 B row limit (ruling R-c2). Per world line request source row `src_row(y)` (same
row map as 2.3); read `pic_rd_x = x + par_off`, `par_off = round(64*cam/230)` metres
(`render.py:93`, round-half-to-even) = `round(64*cam / (230*Q))` in units. Load the picture on stage entry and
on every level change. `cr_level` changes only inside a restart, but a restart can happen in the middle of a
frame, so latch it per frame like the other background inputs.

## 8. Timing notes for the Vivado run

`cr_core` runs one box per two clocks and is far inside its budget (slowest step in the scenarios 6 252 clocks
of ≈ 833 000), so any path that fails timing can get a pipeline register without changing behaviour. Paths to
look at: 48-bit compare chains in the box walker (`under_b`, `touch_b`, `bk_hit`), the `place_reporter`
candidate (`pc_s`), the 55-bit animal height product, and the unrolled 32-step LFSR for the question pair.
